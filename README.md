# Issue Bot

AI-powered issue creator for Mattermost. Type a slash command, get a fully structured GitLab or GitHub issue — title, description, labels, acceptance criteria — generated by an LLM and ready to approve with one click.

```
/issue 3 Build login page with OAuth support
```

```
┌───────────┐     ┌──────────┐     ┌─────┐     ┌────────────┐
│ Mattermost│────▶│ Issue Bot│────▶│ LLM │────▶│ GitLab /   │
│  /issue   │◀────│ (FastAPI)│◀────│     │     │ GitHub API │
└───────────┘     └──────────┘     └─────┘     └────────────┘
     preview with                  structured
  [Approve] [Edit] [Cancel]        JSON issue
```

## Features

- **AI issue generation** — Describe what you need in plain English, get a structured issue with summary, context, acceptance criteria, and technical notes
- **Interactive preview** — Review the generated issue in Mattermost with Approve, Regenerate, Edit, and Cancel buttons
- **Multi-project** — Route issues to different GitLab/GitHub projects with `/issue frontend 3 ...`
- **Templates** — `bug`, `feature`, `chore` templates that guide the LLM to include relevant sections (steps to reproduce, user stories, etc.)
- **Epic creation** — `/issue epic 8 Build auth system` generates a parent issue + 3-8 child tasks
- **Sprint planning** — `/issue plan Build auth, add profiles, notifications` generates a batch of independent issues
- **Search & list** — `/issue list` and `/issue search <query>` to browse existing issues
- **Webhook notifications** — Get Mattermost channel notifications when GitLab issues are opened, closed, or reopened
- **Assignees, milestones, iterations** — Full edit dialog with dropdowns pulled from your project
- **Multiple LLM providers** — OpenAI, Anthropic, Ollama, Gemini
- **Persistent storage** — SQLite-backed pending issues and creation audit log
- **GitHub support** — Use GitHub repos alongside GitLab projects

## Commands

| Command | Description |
|---|---|
| `/issue <points> <prompt>` | Create an issue in the default project |
| `/issue <project> <points> <prompt>` | Create in a specific project |
| `/issue bug\|feature\|chore <points> <prompt>` | Create with a template |
| `/issue help` | Show commands, projects, LLM config, labels |
| `/issue list [project]` | List recent open issues |
| `/issue search <query>` | Search issues by text |
| `/issue epic <points> <prompt>` | Create a parent + child issues |
| `/issue plan <goals>` | Generate a batch of sprint issues |

### Examples

```bash
/issue 3 Build login page with OAuth support
/issue frontend 5 Add dark mode toggle to settings
/issue bug 2 Login crashes on Safari when using SSO
/issue feature 8 Add user profile page with avatar upload
/issue epic 13 Build complete notification system
/issue plan Build auth, add user profiles, set up CI/CD
/issue list backend
/issue search authentication
```

## Installation

### Docker (recommended)

```bash
git clone <repo-url> issue-bot && cd issue-bot
cp .env.example .env
# Edit .env with your tokens (see Configuration below)
docker compose up -d
```

### Bare metal

Requires Python 3.12+.

```bash
git clone <repo-url> issue-bot && cd issue-bot
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# Edit .env with your tokens
uvicorn app:app --host 0.0.0.0 --port 8321
```

### Production deploy (systemd)

```bash
# On your server
chmod +x deploy.sh && ./deploy.sh
sudo nano /opt/issue-bot/.env       # add your tokens
sudo systemctl enable --now issue-bot
```

Add to your nginx config:

```nginx
location /bot/ {
    proxy_pass http://127.0.0.1:8321/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

## Configuration

### Required

| Variable | Description |
|---|---|
| `GITLAB_TOKEN` | GitLab personal access token with `api` scope |
| `MM_SLASH_TOKEN` | Mattermost slash command verification token |

### Single project (legacy mode)

| Variable | Description |
|---|---|
| `GITLAB_PROJECT_ID` | GitLab project ID or URL-encoded path |
| `PROJECT_LABELS` | Comma-separated list of valid labels |
| `GITLAB_URL` | GitLab instance URL (default: `https://gitlab.com`) |

### Multi-project mode

Set `GITLAB_PROJECTS` as a JSON object instead of `GITLAB_PROJECT_ID`:

```env
GITLAB_PROJECTS={"frontend":{"id":"123","name":"Frontend","labels":"bug,feature"},"backend":{"id":"456","name":"Backend API","labels":"bug,infra"}}
GITLAB_DEFAULT_PROJECT=frontend
```

Each project supports:
- `id` — GitLab project ID (or `owner/repo` for GitHub)
- `name` — Display name shown in previews
- `labels` — Comma-separated available labels
- `backend` — `gitlab` (default) or `github`

### LLM provider

| Variable | Description |
|---|---|
| `LLM_PROVIDER` | `openai` (default), `anthropic`, `ollama`, or `gemini` |
| `LLM_API_KEY` | API key for your provider |
| `LLM_MODEL` | Override model (leave blank for provider default) |
| `LLM_BASE_URL` | Override endpoint (required for Ollama) |

**Provider defaults:**

| Provider | Default model | Notes |
|---|---|---|
| openai | `gpt-4o` | Best all-round |
| anthropic | `claude-sonnet-4-5-20250514` | Great structured output |
| ollama | `llama3` | Free, self-hosted |
| gemini | `gemini-2.0-flash` | Cheap, fast |

### Optional

| Variable | Default | Description |
|---|---|---|
| `BOT_URL` | `http://localhost:8321` | Bot's public callback URL |
| `MM_SITE_URL` | `http://localhost:8065` | Mattermost server URL |
| `BOT_DB_PATH` | `data/issuebot.db` | SQLite database path |
| `GITLAB_WEBHOOK_SECRET` | — | Secret for GitLab webhook verification |
| `MM_BOT_TOKEN` | — | Mattermost bot token for channel posting |
| `MM_NOTIFY_CHANNEL_ID` | — | Channel ID for webhook notifications |
| `GITHUB_TOKEN` | — | GitHub personal access token |
| `GITHUB_URL` | `https://api.github.com` | GitHub API base URL |

## Mattermost Setup

1. Go to **Main Menu → Integrations → Slash Commands → Add Slash Command**
2. Set:
   - **Trigger Word:** `issue`
   - **Request URL:** `https://your-domain.com/bot/slash/issue`
   - **Request Method:** POST
   - **Autocomplete Hint:** `[project] [template] <points> <description>`
3. Copy the **Token** into your `.env` as `MM_SLASH_TOKEN`

## Webhook Notifications

To receive Mattermost notifications when issues change in GitLab:

1. Set `GITLAB_WEBHOOK_SECRET`, `MM_BOT_TOKEN`, and `MM_NOTIFY_CHANNEL_ID` in `.env`
2. In GitLab → **Settings → Webhooks**, add:
   - **URL:** `https://your-domain.com/bot/webhooks/gitlab`
   - **Secret token:** same as `GITLAB_WEBHOOK_SECRET`
   - **Trigger:** Issue events

## Architecture

```
app.py              FastAPI routes + wiring (~490 lines)
config.py           Config loading, project resolution
parser.py           Slash command parser (sub-commands, projects, templates)
store.py            SQLite storage (pending issues + audit history)
llm.py              LLM abstraction (single, epic, plan prompts)
gitlab.py           GitLab API (issues, members, milestones, search)
github.py           GitHub API (issues, search, collaborators)
mattermost.py       Message/dialog builders, bot posting
templates.py        Issue templates (bug, feature, chore)
```
